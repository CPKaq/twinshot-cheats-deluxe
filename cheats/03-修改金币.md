# 说明书:修改金币

> 状态:**已实现 + 已实测通过 ✅**(F5 +100;真实值立即生效并持久化;UI 为显示层缓存,面板 Show 时刷新——已定性为预期行为,不追 UI 读取点)

## 1. 效果定义

- 玩家看到的最终效果:修改金币数值
- 生效范围:游戏存档总金币
- 建议的交互形态:**动作型**——按 F5 一次 +100(或按住连加),而非锁定(锁定金币的语义是另一条作弊,见 §3 路线 B)

## 2. 静态分析结论(dnSpy)

| 项 | 值 |
|---|---|
| 程序集 | Assembly-CSharp.dll |
| 类完整签名 | `SaveData` (全局) |
| 目标字段/方法签名 | `public static int GetCoins()`, `public static void SetCoins(int value)` |
| 类型 | int / void |
| 行为描述 | 读写 `SaveData.Backing` 键值存储中的 `"coins"` 条目;Set 自带 `Save()` 持久化 |

**关键结论:金币没有专属字段/类,不需要继续找变量。** 它是键值存储里的条目,继续挖字典内部布局没有必要——用游戏自己的 Get/Set 方法即可。

### 关键代码摘录(附 dnSpy 行号)

```csharp
	// Token: 0x06000436 RID: 1078 RVA: 0x000324D4 File Offset: 0x000306D4
	public static int GetCoins()
	{
		return SaveData.Backing.GetInt("coins", 0);
	}

	// Token: 0x06000437 RID: 1079 RVA: 0x000324E6 File Offset: 0x000306E6
	public static void SetCoins(int value)
	{
		SaveData.Backing.SetInt("coins", value);
		SaveData.Backing.Save();
	}
```

## 3. 实现选型(Phase 3)

- [ ] 写字段(锁数值)-> 不推荐:值在键值存储内部,要读字典布局,脆弱
- [ ] patch 方法(直接返回或改参数)-> 路线 B 备选
- [x] 调用游戏自己的方法 -> **路线 A(推荐)**:`mono_runtime_invoke` 反射调用 `SetCoins`/`GetCoins`

**路线 A(推荐):反射调用 Get/Set(动作型,加金币)**
- `mono_runtime_invoke(SetCoins, NULL, args={&value}, &exc)`——静态方法,无需实例;
- 读当前值用 `GetCoins`(返回装箱 int,取 `+0x10` 处的 int);
- 热键 F5:+100 一次;trainer 框架的 `action` 槽位即为此设计(已实现);
- 优点:改的是真实数值、走游戏自己的 `Save()` 持久化、不碰存储布局。

**路线 B(备选,姊妹项"免费购买"):patch `GetCoins` 恒定返回大数**
- `mov eax, 0x000F424F; ret` (B8 4F 42 0F 00 C3) → 一切读金币的地方都看到 99,999,999;
- 语义是"永不缺钱"(显示值冻结);真实存档值不变;
- 若做,另开说明书(如 `03b-免费购买.md`),不与路线 A 混在同一项。

**理由**:用户效果定义是"修改存档总金币"——即改真实值,路线 A 精准匹配且复用游戏持久化;路线 B 是"无限钱"语义,不同作弊。

理由(原文):金币在键值存储里,写字段需读字典内部布局;方法已在,反射调用是最短路径。
