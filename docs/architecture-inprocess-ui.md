# 进程内 UI(B1)设计与对接说明

> 形态:**单 DLL,进程内 UI**——`trainer.dll` 注入后自动弹出一个独立 Win32 窗口,
> Insert 键显隐。UI 与后端核心同项目编译,**零 IPC,直接调用 `TrainerApi`**。
>
> **状态:B1 为过渡/回退形态。** 正式 UI 采用外置前端(方案 A),见
> `docs/architecture-frontend-standalone.md`;其 §12 列出了正式 UI 验收后
> 可从 `trainer/trainer.cpp` 清理的 B1 代码、依赖与文档。
>
> 实现:`trainer/trainer_api.h`(接口层)+ `trainer/trainer.cpp` 的"进程内 UI(B1)"段;
> 外部前端(A 形态,管道协议)见 `docs/architecture-frontend.md`。

## 1. 架构总览

```
┌─────────────────────────────────────────────────────┐
│ 游戏进程 Twin Shot Deluxe.exe                        │
│                                                     │
│  ┌───────────────────────────────────────────────┐  │
│  │ trainer.dll                                    │  │
│  │  ├─ UI 线程(Win32 窗口)                       │  │
│  │  │   只调 TrainerApi:GetSnapshot / Set / Act   │  │
│  │  ├─ 管道线程(A 前端,并存)                    │  │
│  │  │   只收命令→入队 / 发事件                    │  │
│  │  └─ trainer 线程 ★唯一允许调 mono 的线程★      │  │
│  │      消费命令队列 → 定位/patch/写内存/反射调用  │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

- **TrainerApi 是正式解耦层**(`trainer_api.h`):两种前端(UI、管道)共用同一语义——
  快照读状态、Set/Act 提交命令;
- **三条线程**(UI / 管道 / trainer)中,前两条只入队、不碰 mono;
  这是 Mono 运行时线程亲和性的硬约束,与"是否进程内"无关,队列省不掉;
- UI 与热键、管道前端三方并行操作,状态由**快照轮询**统一回显,天然不冲突。

## 2. UI 规格

| 项 | 值 |
|---|---|
| 窗口 | 独立顶层窗口 `Twin Shot Trainer`(不 hook 游戏渲染,不吃游戏输入) |
| 弹出时机 | 注入成功即弹窗(`ShowWindow(SW_SHOW)`) |
| 显隐 | **Insert 键**边沿检测切换;窗口顶置(WS_EX_TOPMOST) |
| 关闭按钮 | = 隐藏(不退出,游戏继续) |
| 每作弊一行 | `STATIC 标签(名字 [热键])` + 控件:开关型=复选框(BS_AUTOCHECKBOX),动作型=按钮(BS_PUSHBUTTON) |
| 动作数值 | 底部 `EDIT`(ES_NUMBER,默认 100)——动作型作弊(如金币)的步长,**与热键默认值独立** |
| 状态回显 | 100ms 定时器:`TrainerApi_GetSnapshot` 同步复选框状态 + `EnableWindow`(未 ready 置灰) |

## 3. 线程契约与数据流

- UI 线程内**只发生**两件事:
  1. `TrainerApi_GetSnapshot`(线程安全短临界区拷贝,不触碰 mono);
  2. `TrainerApi_Set / Act`(入队,立即返回)——点击 ≠ 生效,生效靠快照回显;
- 命令在 trainer 线程消费执行(与热键、管道命令同一队列、同一契约);
- 因此 UI 无需任何锁之外的知识,新增作弊项后 UI **自动多一行**(快照驱动渲染)。

## 4. 参数化动作(与热键的关系)

| 入口 | 步长语义 |
|---|---|
| 热键 F5 | 固定默认值 100(每次按下重置为默认) |
| UI"执行"按钮 | 读"动作数值"输入框;`<= 0` 兜底 100 |
| 管道 `act` + `amount` | 命令携带;`<= 0` 保留当前值 |

三者共享同一 `Cheat.arg` 槽,动作函数只看 `c.arg`。

## 5. 风险与注意事项

- **UI 崩溃 = 游戏崩溃**(同进程)。对策:UI 保持极简(纯 Win32 原生控件、
  零第三方库、零动态分配),这条已写进代码注释,改 UI 时勿引入复杂依赖;
- UI 线程**绝不能**直接调 mono 或读游戏对象——快照里的字符串都是静态串,
  拷贝只发生在 trainer 线程的临界区内;
- 卸载:`g_run=false` 后 UI 消息循环退出;强制卸载(FreeLibrary)时不等待
  UI 线程,窗口由进程退出回收(与管道线程同一策略)。
